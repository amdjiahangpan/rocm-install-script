# ROCm 7.14 Guided GPU and Runfile Fallback Design

## Goal

Expand the ROCm 7.14 installer across the official Radeon and Ryzen GFX families without pretending that model names provide PCI IDs, guide users when automatic detection is unavailable, recommend `gfx=all` for heterogeneous systems, and add an explicit official Runfile fallback.

## Sources

The implementation uses two references with different authority:

- Official ROCm 7.14 installer selector: <https://rocm.docs.amd.com/en/latest/install/rocm.html?fam=all&w=compute&os=ubuntu&ubuntu-ver=24.04&i=runfile>
- Chinese model-to-GFX convenience table: <https://github.com/amdjiahangpan/hello-rocm/blob/master/docs/zh/00-environment/rocm-gpu-architecture-table.md>

The official selector defines supported models, GFX targets, installation methods, and the Runfile command. The convenience table is displayed for lookup only. Neither source is treated as a PCI device/revision database.

`fam=all` is only a documentation selector. The actual all-architecture fallback is the Runfile argument `gfx=all`.

## GPU selection

### Working KFD

A valid KFD inventory containing only reviewed GFX targets is authoritative for architecture selection.

- Known PCI mappings remain strict consistency checks.
- An AMD display device that is bound to `amdgpu` but absent from the local PCI-to-GFX table does not invalidate otherwise valid KFD evidence.
- Such a plan records `gpu_source=kfd+unmapped-pci` and lists the unmapped PCI IDs.
- The complete KFD GPU-node count is retained as `gpu_count`; duplicate GFX targets still collapse for package selection.

This lets Radeon AI PRO R9700 and other official models work before every PCI revision has been curated locally.

### Missing KFD

When KFD has no valid GPU nodes:

1. Known reviewed PCI IDs may recover the GFX automatically.
2. Unknown PCI IDs in an interactive run display both lookup links and prompt for:
   - model name, stored only for display;
   - GFX target, validated against the reviewed ROCm 7.14 artifact table.
3. A non-interactive run requires `--gpu-arch`.
4. After driver activation, the manually selected GFX must agree with KFD before any architecture-specific ROCm installation.

Model text never selects a package, kernel, or driver.

## Heterogeneous GPUs

When more than one distinct GFX target is detected, the plan prints a prominent recommendation for:

```bash
sudo ./rocm-install.sh --method runfile --gpu-arch all --skip-ssh
```

Same-class, policy-compatible multi-GFX APT/PIP/Tarball installs may continue after confirmation. Mixed Ryzen/Radeon/Instinct policy classes remain fail-closed and print the explicit Runfile fallback command.

For repeated identical cards, such as 4×R9700:

- package selection remains one `gfx1201` artifact;
- the plan displays `gpu_count=4`;
- post-install validation requires `rocminfo` to report `gfx1201` and `amd-smi version` to report ROCm 7.14.0;
- per-card HIP execution is not required by this scope.

## Explicit Runfile method

Add `runfile` as a fourth install method.

The only all-architecture form is:

```bash
sudo ./rocm-install.sh --method runfile --gpu-arch all --skip-ssh
```

Rules:

- `all` is rejected for APT, PIP, and Tarball.
- No current APT/PIP/Tarball run silently changes method after a mismatch.
- The script pins `rocm-installer-7.14.0-7.run` from the official `repo.radeon.com` release URL.
- The self-extracting Runfile performs its built-in checksum validation.
- The ROCm command uses `deps=install rocm gfx=all compo=core,core-dev` and the default `/opt` target.
- Driver installation remains under the existing driver state machine; the Runfile path does not install `amdgpu` a second time.
- Existing package-manager and Runfile layouts cannot be mixed. Conflicts stop with an exact uninstall command.
- With explicit `target=/opt`, the installed root is `/opt/rocm/core-7.14.0`, used by Runfile `rocminfo` and `amd-smi` verification.
- Before reinstalling, the script queries Runfile-installed architectures and keeps a matching `all` installation unchanged.
- `--method runfile --uninstall` invokes the same pinned Runfile with `uninstall-rocm gfx=all`; it does not emulate uninstall with recursive deletion.

## Plan and errors

The public plan adds:

- `gpu_count`
- `unmapped_pci` when present
- `lookup_url`
- Runfile artifact URL and `gfx=all` action when selected

An architecture mismatch prints detected KFD, user input, official links, and the explicit Runfile command. It exits nonzero without changing the install method or installing ROCm.

## Validation

Automated tests cover:

- official Radeon/Ryzen GFX targets in the model guide;
- valid KFD plus unmapped bound PCI;
- missing KFD interactive/manual GFX selection;
- non-interactive missing-KFD failure;
- manual GFX versus post-driver KFD mismatch;
- duplicate four-card `gfx1201` inventory and `gpu_count=4`;
- heterogeneous warning and mixed-class fallback message;
- explicit Runfile `gfx=all` plan, download command, install command, idempotence, verification root, and uninstall command;
- rejection of `all` under other methods and rejection of automatic method switching.

The user will run the completed script on the 4×R9700 host and report the resulting plan and `rocminfo` output.
