# ROCm 7.14.0 Installer Design

Date: 2026-07-28
Status: Implemented

## Purpose

`rocm-install.sh` is a standalone installer for the ROCm 7.14.0 compute stack.
It supports Ubuntu 24.04 and 26.04 on `x86_64`, validates one exact supported
KFD gfx architecture, and resolves the full install plan before running any mutation.

The implementation is intentionally fixed:

```text
ROCm release:   7.14.0
Package series: 7.14
AMDGPU release: 31.40
Workload:       compute
Package profile: full Core SDK
```

There is no release selector or network release discovery.

## Supported Data

Runtime tables are embedded in `rocm-install.sh`, so the downloaded script works
without repository files. Test fixtures preserve the reviewed source data.

- 15 architectures: `gfx950`, `gfx942`, `gfx90a`, `gfx908`, `gfx1201`,
  `gfx1200`, `gfx1100`, `gfx1101`, `gfx1102`, `gfx1030`, `gfx1151`, `gfx1150`,
  `gfx1152`, `gfx1153`, and `gfx1103`
- Two OS records: `ubuntu-24.04.4` and `ubuntu-26.04`
- One workload: `compute`

Each architecture record contains its APT package suffix, pip device extra, and
exact tarball filename. The installer maintains no SKU, family, or model table.

## Validation and Plan Resolution

The main flow is:

```text
parse arguments
  -> require root
  -> detect Ubuntu version, x86_64, and running kernel
  -> resolve one KFD gfx architecture or an explicit override
  -> validate OS, architecture, resolved driver mode, kernel, and method
  -> publish and validate the install plan
  -> print the plan and confirm when interactive
  -> migrate the driver before any prerequisite APT transaction
  -> install prerequisites
  -> install ROCm
  -> configure SSH and the system environment
  -> verify or report a pending reboot
  -> apply the reboot policy when required
```

`INSTALL_PLAN` has six required keys and one optional informational key:

```text
gfx os_key repo_slug method artifact driver_mode [product_name]
```

Plan validation checks every key against the embedded records. No package,
repository, driver, or system command runs before plan validation and, for an
interactive install, confirmation.

## GPU Identity

Pre-install detection uses KFD only. It accepts topology nodes whose
`cpu_cores_count` is zero and whose `gfx_target_version` is nonzero, decodes the
decimal target with AMD's major/minor/stepping algorithm, and deduplicates the
result. Exactly one architecture succeeds; zero or multiple targets require
`--gpu-arch`. It does not use `rocminfo`, `lspci`, or `/proc/cpuinfo`.

The product name is informational. The helper first reads DRM sysfs
`product_name`; an empty value falls back to exact device/revision rows in the
installed `amdgpu.ids` database, prefixing `AMD ` for display. It never infers a
SKU, family, driver, kernel, or package from that name.

## OS, Kernel, and Driver Policy

`detect_system` accepts Ubuntu 24.04 or 26.04 on `x86_64`. Ubuntu 24.04 maps to
the 24.04.4 support key.

Kernel validation requires:

| Resolved driver mode | Ubuntu 24.04 | Ubuntu 26.04 |
| --- | --- | --- |
| Inbox | 6.17 HWE | 7.0 GA |
| DKMS | 6.8 GA | 7.0 GA |

The installer doesn't change or lock the kernel. A mismatch fails before any
mutation.

`auto` resolves to inbox. `inbox` removes conflicting DKMS state; explicit
`dkms` installs AMDGPU 31.40 DKMS. Driver mode is independent of product name.

The migration logic checks the `amdgpu-dkms` and `amdgpu-dkms-firmware`
packages and `dkms status`. Inbox directly purges each installed conflicting
package before any prerequisite APT transaction, then verifies that no AMDGPU
DKMS residue remains. DKMS retains a clean 31.40 installation, but removes and
replaces an older, mixed, or malformed installation. Removal must leave no
detected AMDGPU DKMS state before the 31.40 repository is configured.

Cleanup policy behavior is exact:

- `auto` and `ask` request confirmation interactively and reject required
  cleanup in non-interactive mode.
- `always` approves required removal without prompting.
- `never` rejects a migration that requires removal.

## Artifact Methods

### APT

APT is the default. It uses AMD's `packages-multi-arch` repository with the
validated `ubuntu2404` or `ubuntu2604` slug. The selected package is:

```text
amdrocm-core-sdk7.14-<validated-gfx>
```

### Pip

Pip creates `/opt/rocm-7.14.0-venv` and installs this pinned requirement from
`https://repo.amd.com/rocm/whl-multi-arch/`:

```text
rocm[libraries,device-<validated-gfx>]==7.14.0
```

### Tarball

The tarball method selects a filename from the explicit architecture table. It
downloads into a temporary directory, extracts into staging, replaces
`/opt/rocm-7.14.0`, and updates `/opt/rocm` only after promotion succeeds. The
implementation restores the prior root when a later activation step fails and
rollback succeeds.

No method has a generic architecture fallback.

## Retained System Behavior

Required prerequisites include `curl`, CA certificates, GnuPG, `pciutils`, and
`systemd-timesyncd`. They are installed only after the driver migration phase
has succeeded. Pip adds Python virtual environment packages. Tarball adds `tar`
and `gzip`. A separate optional APT operation installs the retained development
and administration tools; its failure is reported but isn't fatal.

The script also:

- enables `systemd-timesyncd` and NTP;
- installs and starts OpenSSH unless `--skip-ssh` is set;
- writes an SSH drop-in that permits root login and password authentication;
- changes the root password only when `--root-password` is supplied and SSH
  setup runs;
- adds the invoking user to `video` and `render` when needed;
- manages GPU udev rules, linker paths, and `/etc/profile.d/rocm.sh`;
- leaves user shell startup files unchanged.

Driver, group, and udev changes set an in-memory reboot-required flag. A
required reboot is immediate by default, may be delayed from 0 to 120 minutes,
or may be skipped. The script doesn't keep persistent install or reboot state.

## Verification and Uninstall

Verification reports a pending reboot when the current install run changed a
driver, group, or udev rule. Otherwise post-install verification requires
successful output from `rocminfo` and `amd-smi version`, and checks that
`amd-smi` reports 7.14.0.

Uninstall purges every architecture-specific full SDK package candidate,
removes the two fixed 7.14.0 install roots, removes `/opt/rocm` only when it is
the expected link, and deletes the installer-managed ROCm repository, key,
profile, linker, and udev files. It reloads linker and udev configuration.

The uninstall path leaves `amdgpu-dkms` installed. It also leaves SSH setup,
the AMDGPU repository, optional tools, NTP settings, and group membership in
place.

## CLI Surface

The implemented options are:

```text
--method apt|pip|tarball
--gpu-arch ARCH
--driver-mode auto|inbox|dkms
--skip-ssh
--root-password PASS
--skip-reboot
--reboot-delay 0..120
--verify-only
--uninstall
--non-interactive
--dkms-cleanup auto|ask|always|never
--help, -h
```

`--verify-only` and `--uninstall` are mutually exclusive. Interactive mode asks
once before installation, asks before DKMS removal when the selected policy
requires it, and asks before uninstall. Non-interactive mode skips install and
uninstall confirmation but doesn't turn `auto` or `ask` into cleanup approval.

## Test Boundary

`ROCM_INSTALL_LIBRARY_MODE=1` lets the shell tests source the script without
calling `main`. Pure functions validate records and plans. Stateful tests replace
`run_cmd`, command capture, password updates, and managed-file writes so they can
assert ordering and failure behavior without changing the host.

The practical suite covers release and CLI behavior, exact GPU detection,
artifact commands, lifecycle ordering, DKMS migration, system setup,
verification, reboot, and uninstall.
